# Ascension addon compatibility baseline

Source of truth: the exact addon archives supplied from the RetreatUI launcher environment on 2026-08-19.

## Audited builds

| Addon | Audited version | SavedVariables / profile source |
|---|---|---|
| WeakAuras | 5.21.2 (`X-Flavor: 3.3.5`) | `WeakAurasSaved` |
| ElvUI | 7.27 | `ElvDB`, `ElvPrivateDB`, `ElvCharacterDB` |
| Details | `#Details.20240508.12893.160` | `_detalhes_global`, `_detalhes_database` |
| TurboPlates | 1.4.5 | `TurboPlatesDB` |
| DBM | 5.21 / revision 5021 | `DBM_SavedOptions`, `DBT_SavedOptions` plus module SavedVariables |

## WeakAuras 5.21.2

The Ascension package exposes `WeakAuras.Import(inData, target, callbackFunc, linkedAuras)`.

Important contract:

- A string import is expected to be a normal WeakAuras encoded transmission.
- A table import is expected to be a transmission envelope with `d` containing the root display, optional `c` children, and `v` transmission version.
- A raw display table must **not** be passed to `WeakAuras.Import` as if it were an import envelope.
- `WeakAuras.Import` runs `WeakAuras.PreAdd` and then opens the native WeakAuras update/import UI.
- `WeakAuras.PreAdd` validates the display against the current region defaults and current data stub.
- The public `WeakAuras.NewAura(sourceData, regionType, targetId)` exists in WeakAurasOptions, but RetreatUI will not use it for bulk installs because it immediately creates displays.

RetreatUI policy:

- No direct `WeakAuras.Add` for Tracker Builder generated content.
- No RetreatUI LibDeflate/LibSerialize decoding of WeakAuras transmissions.
- No bundled per-class WeakAura packages in the new Tracker Builder architecture.
- Tracker Builder will build native, data-only display definitions and send a package through WeakAuras' own import/update flow.
- No custom trigger Lua is generated by the basic tracker templates.

## ElvUI 7.27

ElvUI exposes the Distributor module through `E:GetModule("Distributor")`.

Native profile functions:

- `Distributor:ExportProfile("profile", "text")` returns profile key plus a native `!E1!` profile string.
- `Distributor:ImportProfile(dataString)` decodes and applies through ElvUI's own importer.
- Existing profile names are handled by ElvUI's normal overwrite prompt.

RetreatUI policy:

- Unified RetreatUI profiles store the native ElvUI text export rather than rebuilding ElvUI tables.
- Imports go through the Distributor module.

## Details

Native functions:

- `Details:ExportCurrentProfile()` returns the printable compressed profile string.
- `Details:ImportProfile(profileString, profileName, importAutoRunCode, isFromImportPrompt, overwriteExisting)` imports it.
- `Details:ApplyProfile(profileName, ...)` activates the imported profile.

Important finding:

The audited Ascension Details build does **not** require or emit a `D!ProfileV2-` prefix. Its native export is the direct `LibDeflate:EncodeForPrint` result from `Details:CompressData(..., "print")`.

RetreatUI policy:

- Do not require `D!ProfileV2`.
- Store the exact native string returned by `ExportCurrentProfile`.
- Import with auto-run code disabled and verify the target profile exists before activation.

## TurboPlates 1.4.5

TurboPlates has native `ns:ExportSettings(options)` and `ns:ImportSettings(importString, options)` functions using the `!TP1!` format.

The addon namespace `ns` is private to TurboPlates and is not exposed as a public global API in the supplied build. RetreatUI must not use debug/upvalue tricks to reach it.

RetreatUI policy for the current exact launcher build:

- Capture `TurboPlatesDB` as validated data-only profile data.
- Record the source addon version with the captured data.
- Refuse automatic application when the installed TurboPlates version differs from the captured version.
- Back up the existing `TurboPlatesDB` before applying and require a UI reload.
- If TurboPlates later exposes a public import/export API, prefer that native API.

## DBM 5.21 r5021

The supplied Ascension DBM uses `DBM_SavedOptions` and `DBT_SavedOptions` as its core character SavedVariables. Raid/module addons use separate per-character SavedVariables.

The separately supplied `DBMSavedVariablesUpdate.zip` contains `DBM_AllSavedOptions` and `DBT_AllPersistentOptions`, which belong to a newer DBM SavedVariables model and do not match this Ascension DBM core.

RetreatUI policy:

- Do not deploy that SavedVariables zip to this DBM build.
- Any future unified DBM profile support must capture/apply the actual Ascension variables and version-gate the data.

## Stability rule

All addon adapters must fail closed: missing addon, wrong version, unavailable native API, invalid data, combat lockdown, or failed verification returns an error to RetreatUI instead of attempting a fallback mutation path.
